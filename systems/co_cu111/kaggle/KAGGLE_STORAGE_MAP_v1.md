# CO/Cu(111) L15/L17 Kaggle storage map v1

This file is the permanent pointer map for the resilient L15/L17 site-depth diagnostic.

## Rule of record

A Kaggle notebook VM is disposable. `/kaggle/working` and `/kaggle/tmp` are session workspaces, not the authoritative checkpoint store. The authoritative restart state is the newest hash-verified private Kaggle dataset slot accepted by `kaggle_l15_l17_resilient_v3.py`.

## Durable checkpoint store

Authenticated Kaggle user: `symcuniverse`

Private ping-pong datasets:

- `symcuniverse/symc-co-cu111-l15-l17-checkpoint-a`
- `symcuniverse/symc-co-cu111-l15-l17-checkpoint-b`

Each durable slot uses:

- `CHECKPOINT_META.json` for checkpoint serial, case identity, archive size, archive SHA-256, route SHA-256, protocol SHA-256, and completed-case list.
- `symc_checkpoint.qebin` for the uncompressed tar snapshot containing the active QE checkpoint, preserved completed results, or both.

A slot is resumable only after metadata, archive size, archive SHA-256, route identity, protocol identity, and QE checkpoint manifest verification pass. The orchestrator chooses the newest valid serial automatically. A filename or dataset timestamp alone is never enough.

## Session-local paths

These paths are regenerated or restored when a notebook session starts:

- Repository clone: `/kaggle/working/Chemistry`
- Small preserved result tree: `/kaggle/working/symc_l15_l17_results`
- Preflight record: `/kaggle/working/KAGGLE_L15_L17_PREFLIGHT.json`
- Latest persistence receipt: `/kaggle/working/KAGGLE_L15_L17_PERSISTENCE_STATUS.json`
- Human-readable pointer file generated by the startup script: `/kaggle/working/SYMC_STORAGE_POINTERS.txt`
- Large active QE checkpoint: `/kaggle/tmp/symc_l15_l17_active`
- Next microsegment staging area: `/kaggle/tmp/symc_l15_l17_next`
- Remote-restore staging area: `/kaggle/tmp/symc_l15_l17_restore`
- Persistence staging area: `/kaggle/tmp/symc_l15_l17_persist_stage`
- Verified engine/bootstrap extraction: `/kaggle/tmp/symc_l15_l17_resilient_bootstrap`

## What survives a new Kaggle VM

The two private Kaggle datasets are the durable store. The local `/kaggle/working` and `/kaggle/tmp` trees may be absent in a new session. Their absence does not imply checkpoint loss.

## Fresh-session entrypoint

Run `FRESH_SESSION_BOOTSTRAP_v1.sh`. It recreates the repo clone, verifies the `personal-free-compute` branch, writes the local storage pointer file, validates native Kaggle authentication, and launches `kaggle_l15_l17_resilient_v3.py`. The orchestrator then queries both private slots and restores the newest verified checkpoint before any new QE segment starts.

## Scientific firewall

This storage/bootstrap layer does not alter the frozen L15/L17 science. In particular it does not alter the 2x2 diagnostic, 0.25 ML coverage, K8 mesh, cutoffs, pseudos, ESM settings, direct-one-rank execution, 0.005 eV/CO sensitivity gate, original L17 clean-surface HOLD, or the frozen QE `max_seconds=16200` input. The scheduled `prefix.EXIT` request and microcheckpoint serials are execution bookkeeping only.
